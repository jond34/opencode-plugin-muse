# Decision coverage: what is decided, what is not

**Written** 2026-11-22. Categorical, not narrative. The question is not "is the
plugin good" but "for each dimension this integration has to answer, is there an
answer, and is it a decision or an omission".

Status codes:

- **H — have.** Implemented and exercised by the suite or a live run.
- **D — decided against.** A written reason exists (`A#` = `steady-state.md`).
- **P — partial.** A decision exists but does not cover the whole dimension.
- **U — not considered.** No decision found in `docs/` or `src/`. Grepped for the
  term, not assumed.
- **X — impossible.** The wire or the vendor forbids it.
- **N — harness-supplied.** opencode owns it; not this layer's question.

The interesting column is **U**. Everything else is already defensible.

The evidence behind each row, and the experiment for each open one, is in
`decision-evidence.md`. Several rows were corrected after that check — U6, U8,
U11, P2, P4 — and nine closed on measured evidence rather than on argument: U2,
U3, U4, U6, U7, U8, U9, U10 and P4. Round 3 closed ten more: U5, U11, U12, U13,
U14, U15, P1, P2 and P3 by decision and implementation.

**Round 15 audit (HEAD `b40aa81`).** Round 14 shipped `--strict` as opt-in, and the survey behind that choice rested on one cell: `brew doctor` said not to gate. It gates — `def self.checks(type, fatal: true)` with `exit 1 if failed && fatal`, and the manpage says non-zero on any finding — so the tally that carried the polarity was inverted (E-D81). Reading the field correctly adds the axis the tally missed: where the severity is the user's (eslint rule levels, rustc lints, yamllint's per-rule levels, `analysis_options`) warnings are advisory and the gate is opt-in; where it is the tool's (shellcheck, `npm audit`, brew, `git diff --check`, `flutter analyze`) the gate is on. This doctor authors its own statuses, so the axis points at gating. Two measurements said the flip was safe: the narrow set never fires on a working checkout (E-D77: exit 0 under the old flag while `host` and `plugins` warn), and nothing reads the code (`scripts/` is absent from the tarball and from every caller, E-D78). The default now gates a refused file, a dropped statement and an unanswered run; `--no-strict` reports only; `--strict` also fails an explicit `--offline`, which the default exempts because the user asked it not to look (D75–D77). D68's two reasons survive as reasons for the narrow row set, not for the flag. `--json` shares the contract (D77); the records call this a local gate, since a runner without a host always exits 1 and that is the honest answer rather than a useful gate (D78); `plugins` stays advisory (D79); no `gate` field joins the report (D80). The live table is 0 1 1 1 by default, 0 0 0 0 under `--no-strict`, 0 1 1 1 under `--strict`, 1 with the host absent, and 0 then 1 for `--offline` and `--offline --strict`.

**Round 16 audit (HEAD `22f337a`).** Round 15's flip was right and its rule was a proxy: "tool authors the severity ⇒ gate" reads as "who invents the finding", and `rustc` is the counterexample — `dead_code` and `unused_import` are rustc's own, on by default, and the build exits 0 (E-D85). The rule that survives is the property: a finding gates when it means a declaration the user made is not in force, which is what a refused file, a dropped statement and an unanswered run are; a compiler warning is not. `nginx -t` passing a conflicting `server_name` with 0 is the boundary the property does not cover (E-D86). The same reading exposed `--strict` as a flag with no cell of its own: it changed `exitCode` only inside `!asked`, so it was reachable only as `--strict --offline`, and a five-tree, four-mode matrix found exactly one cell between the shipped ladder and a two-flag scheme — `--offline` alone, 0 → 1 (E-D82). Nothing called it (E-D83), and elsewhere `--strict` means warnings fail (E-D89), so it is deleted: the gate is `--no-strict` alone, `--offline` only stops the spawn, and `--offline --no-strict` is the report-only offline run (D83, D84). One exit code stays (D71, E-D84): the field splits "could not evaluate" from "found problems" but not on a number — `2` is the former in eslint and grep and the latter in `git diff --check` — and CI collapses both; the diagnostics cost is recorded with its flip condition (D85). `plugins` stays advisory (D86). The test table drops to ten rows, and the spawned `--offline` test covers both invocations.

**Round 17 audit (HEAD `55fc3ad`).** Round 16's gate survived the owner's critique with a wider witness set and three corrections, and the owner kept the four defaults the round raised: gate-on, the flag, one code, and the divergence in this file only (Q1–Q4). The doctor class does not split 3–1 against gating: `codex doctor`, `brew doctor`, `expo-doctor` and `ripr doctor` gate their required checks, Vue Doctor and `claude doctor` require nothing, and `flutter doctor`'s numeric mapping is unpinned — 4–2–1, and the axis is which checks are required rather than whether the tool exits non-zero (E-D97). `codex doctor` is the charter this row cites and exits 1 on `Fail` only, never on `warn`, which is this row's narrow set; Vue Doctor's `--fail-on none` is about findings that are a quality score, and its `--strict` (exit 3 on an analyzer failure) is the semantic round 16 deleted the flag for (E-D96, E-D98). So round 16's "`--strict` means warnings fail everywhere else" was too strong: yamllint, `poetry check` and `composer validate` mean warnings-fail, Vue Doctor means analyzer-failure, and the deletion rests on reachability (D82, D83), not on the name (D89). The field's 2/3 is always the tool's own setup — alint's `.alint.yml`, eslint's config, Vue Doctor's analyzer, ripr's input/config/policy — and this doctor has none; its only config is the user's, and a refused file there is a finding, so the class has no referent here (E-D95). Report-only is a fork, not a settled question: a flag here, two verbs in ripr, off by default in Vue Doctor, absent in codex/brew/expo; the flag stays because it is the only shape with one command, and the flip condition is a consumer that needs report-only by default (E-D99). `compatibility.md` now names the divergence from `claude doctor` — it names a malformed file and exits 0, and is byte-identical on a misspelt key, where this doctor names the dropped statement and exits 1 (E-D91) — and round 16 §3 gains the ripr row §8 promised (D90). The README's test count was stale at 419; it is 416.
