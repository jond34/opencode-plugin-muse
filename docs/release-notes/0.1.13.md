# 0.1.13 — local candidate

> Draft only. No GitHub Release has been created, and this version has not been
> published to npm.

This candidate carries the containment, context-ownership, and boundary work
that was measured in the 0.1.12 line but not yet released.

## What changed

- **Private host configuration and a pinned bridge toolset.** Muse starts with
  its own skills, reminders, workflow triggers, context slimming, and foreign
  personal skills disabled. The bridge exposes only `mcp__opencode__*`, so every
  tool call runs through opencode's permission engine.
- **Project hooks need trust.** A repository's `.muse/hooks.json` is refused
  until its exact hash is recorded with `bun run doctor --trust-hooks`;
  `MUSE_ALLOW_PROJECT_HOOKS=1` accepts it for one run. Installed plugin handlers
  are allowed and reported by origin.
- **opencode owns titles and compaction.** Neither spends a Muse turn. The
  transcript is fingerprinted, and a rewritten or compacted history reseeds the
  native session instead of continuing a different conversation.
- **Effort and prompt boundaries.** `model.variant` maps to Muse's closed effort
  vocabulary; `default` omits the field and an unavailable tier fails closed.
  Agent and instruction text is sent as a developer prompt on start and resume.
- **No zero-tool requests.** A primary request with no bridge tools fails before
  `session/start` with an actionable error.

## What did not change

Windows remains best-effort: the runner matrix, installer, resolver, handshake,
and close path are measured, but there is no signed-in desktop result and no
desktop parity claim. Muse still starts in `allowAll`; opencode's rules are the
one gate, and there is no containment behind the bridge. There is no per-turn
cost cap, no offline path, and native history remains opt-in.
